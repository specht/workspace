Die ganze Klasse malt an einem Bild, live: ein Ruby-Server mit WebSockets in drei Schritten (Echo, Nachrichten an alle, die Pixelwand), dazu eine kleine Webseite mit `<canvas>`. Handshake und Frames übernimmt die Bibliothek faye-websocket; die Lernenden kümmern sich um Verbindungen, Verteilen, JSON und das Prüfen fremder Nachrichten. Am Ende gibt eine Person (oder die Lehrkraft) Port 8000 frei, und alle malen gemeinsam. Ein letzter Abschnitt zeigt an einem Zähler, was Threads ohne Lock anrichten. Vorausgesetzt wird »Ein eigener Webserver«.

**Was schiefgeht.** Fehlen die Gems, bricht `ruby server.rb` mit `cannot load such file -- faye/websocket` ab. Nach jeder Änderung den Server neu starten und die Seite neu laden. Läuft kein Server, zeigt die Browserkonsole (<kbd>F12</kbd>) »WebSocket connection failed«.

**Viele Threads.** `flood.js` schickt 200 Pixel an den eigenen Server auf `localhost`. Vier Threads arbeiten eine Warteschlange ab (eine feste Zahl, denn Workspaces begrenzen die Zahl der Threads; ein Thread pro Nachricht scheitert dort bei etwa 160). Ohne Lock steht der Zähler danach weit unter 200, im Test bei 67, weil die Threads denselben alten Wert lesen, während einer speichert; mit `$lock.synchronize` bei 200. Faye selbst ruft die `on`-Blöcke nacheinander in einem Thread auf, darum brauchen die ersten Stufen keinen Lock. Das Skript erreicht nur den eigenen Server: Shared Live Apps lassen nur angemeldete Browser herein, und Workspaces erreichen einander nicht direkt. Die Seite sagt deutlich, dass das Überschütten fremder Server ein Angriff ist (§ 303b StGB); wer eine geteilte Wand schützen will, baut die Wartezeit pro Verbindung aus den Ideen.

**Die Aufgaben.** »Die Pixelwand« liest `server.rb` und sucht `JSON.parse`, `Faye::WebSocket` und eine Bereichsprüfung, »Ein Lock« `Thread.new`, `Mutex.new` und `synchronize`. Die übrigen fragen nach dem Statuscode 101, wer eine Nachricht bekommt und was der Zähler nach 200 Pixeln zeigt (Vorhersagen), der Größe des Bildes und warum ein Server fremden Nachrichten nicht trauen darf.

**Weiter.** Die Ideen am Ende der Seite, vor allem die Wartezeit pro Verbindung (wie »r/place«), entstehen meist von selbst, sobald die ersten das Bild übermalen.
